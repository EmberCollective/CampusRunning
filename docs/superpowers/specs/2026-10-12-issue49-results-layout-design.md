# Issue #49：生成结果位置、固定下边界与内部滚动

- 关联：[#49](https://github.com/EmberCollective/CampusRunning/issues/49)
- 状态：2026-10-18 按用户验收打回意见返工，待用户重新验收

## 需求与返工原因

结果紧跟当前模式的生成按钮和状态反馈；结果数量增加时，只增加结果内容区的滚动长度，不能继续撑高工作台或页面。

此前 `9c32ca3` 的实现给表格分配了近一屏的 `max-height`，但参数表单仍占据其上方空间，长结果导致右栏超过左栏；短结果又按内容收缩，下边界随行数变化。`a68e88c` 只将文档改为描述该行为，并以表格上限验证通过，漏测了短/长结果的工作台下边界和页面高度，未满足原需求。用户查看截图后明确打回，本次修复实际布局并补充边界回归验证。

## 布局约束

1. 保留当前结果位置与后端 API：配置 → 当前模式参数/生成按钮 → 状态反馈 → 结果。
2. **桌面双栏（>960px）**：工作台两列拉伸到同一个下边界。高度由左栏、当前参数表单和独立的结果槽基准决定，不由表格行数决定。右栏以纵向 flex 把剩余空间分配给结果槽；结果卡底边保留原有的 16px 内边距与 1px 外框边框。因此左右容器底边相等，结果卡始终在右侧容器底边内侧 17px。
3. **单列（≤960px）**：结果槽高度为 `clamp(200px, 40vh, 360px)`（含原有底部内边距），固定占位，不随结果行数收缩或增长。参数表单仍可通过页面滚动访问。
4. **矮窗口**：结果卡高度最多为视口高度减 56px，仍贴在结果槽底部；滚入视野后可同时看到结果标题/下载按钮、固定表头和可滚动的结果内容。不把结果区域的高度上限作为额外空间叠加到整个工作台下面。
5. **状态反馈**：保留至少 54px 的一行反馈槽，提示五秒后消失时不改变结果区下边界。
6. **内容滚动**：只有 `.results-scroll` 允许表格纵向/横向滚动；`min-height: 0` 允许其收缩。固定表头使用不透明背景；`overscroll-behavior: contain` 阻止滚到边缘时将滚动传给整页。滚动区可通过键盘聚焦。窄屏隐藏装饰性格式标签，保留标题与下载按钮。
7. 初次结果出现、短 → 长 → 短、提示消失都不改变当前模式/窗口下的工作台、结果卡和状态条下边界。切换模式可因参数表单本身高度不同改变基线；在每个模式内仍满足上述约束。

## 实现

- `web/templates/index.html`：为状态槽和结果槽添加 class；保持结果相关 ID 与下载入口；为结果滚动区添加可聚焦的 region 语义。
- `web/static/css/style.css`：用 grid/flex 分配与结果内容无关的空间；单列和矮窗口通过 CSS 响应式调整；保持原有内嵌卡片样式。
- `web/static/js/app.js`：删除旧 `updateResultsScrollHeight()`、视口像素上限及 resize/模式切换监听。CSS 自动响应尺寸与表单切换。保留新结果滚回首行、平滑进入视野及下载流程。
- 不修改后端、轨迹编辑器或其他 PR 的功能。
