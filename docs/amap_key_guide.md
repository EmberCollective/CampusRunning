# 高德地图 Key 配置指南

本文档说明轨迹编辑器（`/track-editor`）的四档地图底图方案，以及如何申请高德 Key 并在页面内配置，以解锁「官方」档地图与地址搜索。

## 背景：四档地图源

轨迹编辑器右上角提供四档底图切换，左上角提供地址搜索框：

| 能力 | 说明 | 是否需要 Key |
|---|---|---|
| 经典（默认） | Leaflet + 高德栅格瓦片（`style=8`，含路网与地名标注） | 否 |
| 新版 | Leaflet + 高德栅格瓦片（新版样式） | 否 |
| 卫星 | Leaflet + 高德卫星影像瓦片 | 否 |
| 官方 | 高德官方 JS API 2.0 | **是** |
| 地址搜索 | 左上角搜索框，基于高德 JS API 的 POI 搜索 | **是** |

- 前三档通过 Leaflet 直接加载高德 Web 端公开栅格瓦片（`webrd01~04.is.autonavi.com` 四个子域轮询加速），**无需任何配置，开箱即用**。但该瓦片接口属于非官方承诺端点，不保证长期可用（见文末降级说明）。
- 「官方」档加载高德官方 JS API，具备官方保障与完整功能（含地址搜索），需按下文申请并配置 Key。

本项目所有轨迹坐标均为**高德坐标系（GCJ-02）**，与上述所有底图天然一致，无需坐标转换。

## 申请教程（逐步）

1. **注册账号**：访问 [高德开放平台](https://lbs.amap.com/)，点击右上角注册（支持手机号/邮箱注册）。
2. **实名认证**：进入「控制台」→「账号与安全」完成个人实名认证（企业用途则完成企业认证）。
3. **创建应用**：控制台 →「应用管理」→「我的应用」→「创建新应用」，应用名称随意（如「校园跑步数据生成器」），类型选「其他」。
4. **添加 Key**：在刚创建的应用一侧点击「添加 Key」，**服务平台必须选「Web端(JS API)」**。
5. **同时获得 Key 与安全密钥**：保存后页面会展示两串字符，请一并复制：
   - **Key**：一串 32 位左右的十六进制字符；
   - **安全密钥（securityJsCode）**：**2021 年 12 月之后申请的 Key 强制配套安全密钥**，两者成对使用、缺一不可。

> 注意：Key 类型务必选「Web端(JS API)」。选成「Web服务」类型的 Key 只能用于 REST API（如地理编码），不能用于 JS API，加载地图时会报 `INVALID_USER_KEY` 或 `USERKEY_PLAT_NOMATCH`。

## 在页面内填写

1. 打开轨迹编辑器（`/track-editor`）。
2. 点击**左侧工具栏底部**的齿轮按钮（高德 Key 设置）。
3. 粘贴 **Key** 与**安全密钥**，点击「保存」。
4. Key 保存在**当前浏览器的 localStorage** 中（键名 `te_amap_key` / `te_amap_scode`）：
   - 不会写入项目文件，也不会上传到服务器；
   - 仅对当前浏览器有效，换浏览器/电脑需重新填写。
5. 保存后，右上角第四档「**官方**」与左上角**搜索框**即可使用。
6. **若修改 Key 前官方地图引擎已加载过，需刷新页面**才能让新 Key 生效。

## 常见错误排查

| 报错/现象 | 原因与解决办法 |
|---|---|
| `INVALID_USER_KEY` | Key 不存在、复制不完整或类型选错。确认 Key 类型为「Web端(JS API)」，且前后无多余空格。 |
| `INVALID_USER_SCODE` | 安全密钥缺失或与 Key 不匹配。JS API 2.0 要求 Key 与 securityJsCode 配套使用，回到设置弹窗将两者成对填入。 |
| `USERKEY_PLAT_NOMATCH` | Key 的服务平台与实际调用方式不匹配（如用「Web服务」Key 加载 JS API）。删除该 Key，重新创建「Web端(JS API)」类型。 |
| 加载超时 / 一直显示「加载高德地图…」 | 网络无法访问 `webapi.amap.com`，或 Key 输入有误导致脚本加载失败。检查网络与 Key 后刷新页面重试。 |
| 搜索无结果 | 关键词过偏、该区域无 POI，或 Key 未配置/未生效。可先切换到「官方」档确认地图能正常显示（代表 Key 有效），再更换关键词重试。 |

## 合规说明

- 高德官方 JS API **仅允许在线加载**（从 `webapi.amap.com` 动态引入），禁止下载转存到本地、二次分发或修改后使用，详见高德开放平台服务条款。
- 本项目前三档使用的公开栅格瓦片端点为**非官方承诺端点**，仅供学习研究，高德不保证长期可用，未来存在失效或防盗链的可能。
- 本项目的 Leaflet + 公开瓦片方案是无 Key 场景下的备选实现，不代表高德官方承诺；请自行确保使用方式符合高德开放平台相关条款。

## 附：公开瓦片失效时的降级思路

当公开栅格瓦片接口失效（地图空白/灰块/403）时，配置 Key 并切换到「官方」档即可恢复，无需改动代码。其核心实现思路（Leaflet → AMap，以 JS API 2.0 为例）如下：

1. **动态注入 JS API 脚本**：加载前先设置安全密钥，再引入脚本：

   ```html
   <script>
     window._AMapSecurityConfig = { securityJsCode: 'YOUR_SCODE' };
   </script>
   <script src="https://webapi.amap.com/maps?v=2.0&key=YOUR_KEY"></script>
   ```

2. **API 对照**：

   | Leaflet 写法 | AMap 对应写法 |
   |---|---|
   | `L.map(container, { center, zoom })` | `new AMap.Map(container, { center, zoom })` |
   | `L.marker([lat, lng])` / `L.polyline(...)` | `new AMap.Marker({ position })` / `new AMap.Polyline({ path })` |
   | `L.tileLayer(...)` | JS API 自带底图，无需手动添加瓦片层 |
   | `map.on('click', ...)` | `map.on('click', ...)`（事件对象字段名略有差异） |

3. **坐标无需转换**：两者均直接使用 GCJ-02。唯一区别是**经纬度顺序相反**——Leaflet 处处使用 `[lat, lng]`，AMap 使用 `[lng, lat]`，迁移时需逐处调换。
4. **Key 的存放位置**：不要把 Key 硬编码在前端代码或提交进仓库。本项目将其保存在浏览器 localStorage（`te_amap_key` / `te_amap_scode`），仅在使用者本机生效。
